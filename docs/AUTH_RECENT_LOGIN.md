# 최근 로그인 방식 표시

2026-10-09 · 로그인 화면의 작은 UI 힌트

- 로그인 화면의 Google·카카오·이메일 로그인 버튼 중 이 브라우저에서 마지막으로 성공한 방식 하나에만 `최근 로그인` 배지를 표시한다. 가입/비밀번호 재설정 화면에는 표시하지 않는다.
- 버튼 오른쪽 위의 작은 파란 배지(12px, 600)를 사용한다. 기존 색 토큰과 버튼 문구/크기/포커스를 보존하고, SNS 버튼 간격을 18px로 고정해 표시 여부에 따른 높이 이동을 피한다. 배지는 버튼 접근성 이름에도 포함된다.
- `lib/recent-login.ts`의 `passmate.auth.recent-method`에 `email`, `google`, `kakao` 중 하나만 localStorage로 저장한다. 계정 ID·이메일·이름·토큰·비밀번호는 저장하지 않으며 권한 판단에는 사용하지 않는다.
- 이메일 인증 성공/이메일 로그인 성공/가입 후 세션 생성 시 이메일 방식을 기록한다. OAuth는 기존 로그인 시작 흐름에서 탭 sessionStorage에 방식을 임시 기록하고, 기존 callback이 로그인 세션 성공을 확인하는 지점에서 최근 방식으로 확정한다. 임시 기록은 30분 후 만료되며 성공 후 제거한다.
- 실패·취소·잘못된 저장값·만료된 임시 기록은 마지막 성공 기록을 덮어쓰지 않는다. 저장소 접근 실패는 로그인/리다이렉트를 중단하지 않는다.
- 이전 버전에는 방식 기록이 없으므로 과거 로그인 방식을 추측하지 않는다. 다음 성공 로그인부터 표시하며, 브라우저 데이터 삭제/다른 기기에서는 표시되지 않는다. 단순 세션 갱신과 로그아웃은 이 힌트를 변경하지 않는다.

## 보존 범위

Supabase 설정·OAuth provider/redirectTo·기존 next 경로 검증·세션 처리/인증 조건·주문·결제·다운로드·운영 DB는 변경하지 않는다. 기존 성공/실패 처리 지점에 선택적인 UI 기록만 추가했다. 별도 API나 새 의존성은 없다.

[Supabase 비밀번호 로그인](https://supabase.com/docs/reference/javascript/auth-signinwithpassword), [인증 상태 이벤트](https://supabase.com/docs/reference/javascript/auth-onauthstatechange)의 현재 문서와 저장소 SDK 사용을 확인했다. 인증 상태 callback에서 네트워크 요청이나 비동기 인증 처리를 추가하지 않았다.

## 검증과 롤백

`scripts/validate-browser-storage.mjs`에 시작/취소/성공, 오래되거나 손상된 기록, 저장소 접근 거부 검사를 추가했다. 브라우저 QA는 실제 인증 요청을 로컬 fixture로 가로채 성공/실패/취소를 검사하며 실계정 로그인이나 운영 DB 쓰기를 뜻하지 않는다. 검증 도구/캡처/결과는 워크스페이스 `reports/recent-login-20261009/`에 보관한다.

이 기능의 커밋만 revert하면 기존 로그인 화면과 흐름으로 돌아간다. 새 키는 인증에 사용되지 않아 남아 있어도 기존 버전에는 영향을 주지 않는다. 다른 localStorage나 세션은 삭제하지 않는다.
