# PASSMATE 문제은행 중심 홈 진단과 개선안

2026-10-05 · 디자인 제안과 구현 지시문 · 아직 코드에 적용하지 않음

**D 지시문 최신 기준:** 사용자가 1단계 범위를 확정했다. 코드 적용 시 아래 초기 D 대신 [CBT_HOME_STAGE1_PLAN.md](./CBT_HOME_STAGE1_PLAN.md)를 따른다. 메뉴 통합·하단 탭·토큰 전면 개편·오답 후 노트 연결·이어풀기는 이번 범위에서 제외하며 보조 텍스트는 최소 14px이다.

**1순위는 홈을 자격증 검색과 문제 풀이 중심으로 바꾸는 것이다.** 기존 파랑·네이비와 CBT 기능을 활용한다. 학습 후에는 오답 복습을 먼저 제시하고, 해당 시험의 핵심노트가 있을 때만 스토어를 연결한다.

## 확인 범위와 사실 정정

첨부 스크린샷은 이번 메시지에 전달되지 않았다. 운영 홈과 CBT 화면, 모두CBT PC 실화면, PASSMATE 모바일 실화면 및 현재 로컬 소스를 확인했다. 모두CBT 모바일의 구체적인 배치·치수는 **스크린샷으로 확인 필요**. 이번 진단은 사용자 행동 실험을 수행한 결과가 아니다.

| 사용자 설명 | 확인 결과 |
|---|---|
| 모두CBT 상단에 핵심 메뉴 7개 내외 | 현재 확인한 PC 화면은 **왼쪽 아이콘 사이드바**. 첨부 화면과 버전/폭 차이는 스크린샷으로 확인 필요 |
| 모두CBT 검색·바로가기·통계 | 확인. 구체적인 서비스 이용 수치는 PASSMATE에 차용하지 않음 |
| 모두CBT가 무료를 히어로 전면에 강조 | 현재 확인한 첫 화면에는 해당 문구가 없음. FAQ에 공개 회차 풀이·정답·해설의 비회원 무료 범위가 명시됨 |
| 인기 목록은 탭 | 현재 확인한 PC 화면은 주관식/객관식 **두 열**. 모바일 전환 방식은 스크린샷으로 확인 필요 |
| PASSMATE에는 검색·신뢰 정보·오답 기능이 없음 | `/cbt/`에는 종목 검색, 기출 문항 수 표시, 오답노트·북마크·내 기록이 있음. **루트 홈에 드러나지 않는 문제** |
| PASSMATE는 흑백 미니멀 | 파랑·네이비를 이미 사용. 기존 로컬 토큰의 primary는 `#1d4ed8` |
| 영문 슬로건이 첫 화면 정체성을 흐림 | 확인한 운영 히어로는 한국어. 해당 영문 문구가 눈에 띄는 위치인지 **스크린샷으로 확인 필요** |

출처: [모두CBT 홈과 FAQ](https://www.moducbt.com/), [PASSMATE 운영 홈](https://www.mypassmate.com/), [운영 문제은행](https://www.mypassmate.com/cbt/). 운영 화면과 로컬 브랜치는 다르다. 앞서 완료한 스토어 문구·모바일 개선은 로컬 작업이며 운영 반영으로 간주하지 않았다.

## 가설 검증

| 가설 | 판단 | 근거와 보정 |
|---|---|---|
| 1 홈이 상품 중심이라 문제은행을 이해하기 어렵다 | 타당 · 영향은 검증 전 | 홈 제목·표지·가격·CTA가 상품을 설명. 첫 방문자가 스토어로 인식할 가능성이 높음 |
| 2 내 시험까지 클릭이 많다 | 타당 · 홈 기준 | 검색은 CBT 안에 있음. 홈에서 서비스 전환을 먼저 해야 함. 실제 평균 클릭·이탈은 측정하지 않음 |
| 3 신뢰 요소가 없다 | 부분 타당 | CBT 문항 수·오답 기능은 있음. 이용자 수를 만들지 말고 제공 범위·출처·오류 신고·검수 상태로 신뢰를 보강 |
| 4 색상과 위계가 약하다 | 부분 타당 | 색 부족보다 구매 CTA와 큰 상품 블록에 학습보다 높은 우선순위를 준 것이 문제 |
| 5 영문 슬로건이 문제다 | 우선순위 낮음 | 핵심 문제는 홈의 역할. 영문은 표지 장식에만 남기고 서비스 설명으로 쓰지 않는 방향 제안 |

## A 여섯 축 진단

각 행은 “모두CBT / PASSMATE / 그래서 생기는 문제” 순서다. 심각도는 시험 직전 모바일 수험생이라는 가정에서의 디자인 판단이다.

| 축 | 심각도 | 모두CBT는 이렇게 한다 | PASSMATE는 이렇다 | 그래서 생기는 문제 |
|---|---|---|---|---|
| ① 첫 화면 위계·가치 제안 | 상 | 검색을 중심 행동으로 두고 문제은행 역할을 설명 | 루트 홈이 핵심노트 표지·가격·상품 비교 중심 | 문제를 풀려는 방문자의 첫 행동과 홈이 불일치 |
| ② 네비게이션 | 상 | 기능 진입을 독립된 탐색 메뉴로 제공 | 스토어/문제은행 전환 후 서로 다른 주요 메뉴·브랜드 표시 | 학습과 구매가 다른 서비스처럼 보이고 오답→노트 연결이 끊김 |
| ③ 색상·대비 | 중 | 중립 배경 위에서 작은 강조를 사용 | 파랑·네이비는 이미 있으나 구매 CTA가 강조를 독점 | 색을 늘려도 해결 안 됨. 파랑의 최우선 사용처를 문제 풀이로 바꿔야 함 |
| ④ 타이포·여백 | 중 | 검색과 짧은 목록 중심으로 읽기 순서를 형성 | 홈은 여러 상품 제목·라벨 반복, CBT는 큰 제목과 많은 분류 카드 | 좁은 화면에서 시험 선택보다 설명·장식·전체 분류를 먼저 읽게 됨 |
| ⑤ 카드·버튼 | 중 | 목록 행의 제목·보조 정보로 빠른 스캔 유도 | 상품 카드와 종목 카드가 크고, 종목 분류가 카드 안팎에서 반복 | 목록 길이가 늘고 의미 없는 라벨까지 같은 무게로 보임 |
| ⑥ 모바일 사용성 | 상 | 검색으로 대상 시험을 찾는 구조. 세부 모바일 터치/배치는 스크린샷으로 확인 필요 | 확인한 운영 헤더는 로고·전환·메뉴가 한 줄. 로컬에는 개선안이 있으나 운영은 다름 | 학습 진입이 우회됨. 로컬 공통 로딩 분기도 홈·목록까지 기다리게 함 |

보충: 운영 `/cbt/` 진입 직후 헤더·푸터만 보이고 이후 목록이 나타나는 장면을 관찰했다. 지연 시간을 정량 측정한 결과는 아니다. 로컬 `QuestionBankClient`는 `dataState === "loading"`일 때 화면 전체의 내용을 `QuestionBankLoading`으로 대체하므로, 홈/목록 쉘 분리가 필요하다.

이전 로컬 QA에는 데스크톱 장바구니 버튼 대비 1.37:1이 기록되어 있다. 이번에 운영의 같은 값을 재측정하지는 않았다. 과거 제한 때문에 보존한 항목이며, 재설계 적용 시 공통 접근성 검사에 포함한다.

바로가기는 “인기 자격증”이 아니라 **“바로 풀 자격증”**으로 표기한다. 실측 인기도가 없기 때문이다. 공개된 카탈로그의 실제 종목만 사용하고, 운영자가 정한 노출 순서는 인기 순위로 포장하지 않는다.

### 오답 이후 스토어 연결

```text
채점 결과
  [틀린 문제 다시 풀기]       파란 주 CTA
  [오답노트 보기]             아웃라인

문항 해설·오답 복습 아래
  해당 자격증에 실제 판매 노트가 있는 경우에만
  “컴활 2급 핵심노트로 개념 정리하기” → 기존 상세 페이지
```

| 조건 | 동작 |
|---|---|
| 해당 종목 노트 없음 | 추천 영역 자체를 숨김. 다른 자격증 상품으로 유도하지 않음 |
| 종목↔상품 대응만 있음 | 종목 관련 노트로 안내. “당신의 약점 맞춤” 표현 금지 |
| 단원 분석·원고 매핑 없음 | 특정 단원·쪽수·필요도 점수·개인화 추천을 생성하지 않음 |
| 이미 구매함 | 제공 계약으로 확인 가능할 때만 “내 자료에서 보기” |
| 가격 확인 중/실패 | 기존 skeleton·재시도 유지. 숫자를 하드코딩하지 않음 |

### 디자인 토큰

색 값은 `app/tokens.css`에서만 정의한다. 화면은 역할 변수만 참조한다. 브랜드 파랑은 기존 값을 유지한다.

| 역할 변수 | 라이트 값 | 용도 |
|---|---|---|
| `--color-primary` | `#1d4ed8` | 문제 풀이, 선택 항목, 포커스. 기존 `--blue`와 연결 |
| `--color-on-primary` | `#ffffff` | primary 버튼 글자 |
| `--gray-0 / 50 / 100` | `#ffffff / #f9fafb / #f3f4f6` | 기본 배경 / 섹션 / 비활성 배경 |
| `--gray-200 / 300` | `#e5e7eb / #d1d5db` | 장식 구분선 / 카드 테두리 |
| `--gray-500 / 600` | `#6b7280 / #4b5563` | 부가 정보 / 보조 텍스트 |
| `--gray-800 / 900` | `#1f2937 / #111827` | 강조 텍스트 / 본문·제목 |
| `--color-surface / bg / text / text-muted / border` | 위 팔레트를 참조 | 다크 테마에서 역할 변수만 재정의 |
| `--color-success / error` | 기존 `#257343 / #b5473c` | 정답·오답 전용. 브랜드 강조색과 분리 |
| `--color-focus / overlay / shadow` | primary / 회색 기반 alpha / 회색 기반 alpha | 값은 tokens에 정의, 컴포넌트 하드코딩 금지 |

계산 대비: 흰 배경 기준 파랑 **6.70:1**, gray-600 **7.56:1**, gray-500 **4.83:1**. gray-300을 글자색으로 쓰지 않는다. 실제 조합·투명도·다크 테마는 별도 재검사한다. 정답/오답은 색과 함께 글자·기호로 전달한다.

| 텍스트 | 모바일 크기 / 행간 | PC 크기 / 행간 | 두께 |
|---|---|---|---:|
| 페이지 제목 | 28 / 36px | 40 / 52px | 700 |
| 섹션 제목 | 22 / 30px | 28 / 36px | 600 |
| 카드 제목 | 17 / 24px | 18 / 26px | 600 |
| 문제 본문·일반 본문 | 16 / 26px | 16 / 26px | 400; 문제 강조 600 |
| 보조 정보 | 13 / 21px | 13 / 21px | 400 |
| 필드 라벨·버튼 | 14 / 20px | 14 / 20px | 600 |
| 작은 배지 | 12 / 18px | 12 / 18px | 600 |

폰트는 기존 Pretendard 유지. 영문은 표지 장식·정식 명칭 외에 사용하지 않는다. 아이브로는 분류가 제목에 없을 때만 사용한다.

| 구성 요소 | 수치 |
|---|---|
| 간격 스케일 | 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px |
| 섹션 사이 | 모바일 40px / PC 64px |
| 카드 내부 패딩·간격 | 16px / 8~12px |
| 카드 radius·border | 12px / 1px solid 역할 border 토큰 |
| 카드 shadow | 기본 none. hover/focus 보조로만 `0 2px 8px` + tokens의 회색 6% alpha |
| 주요 버튼 | min-height 48px, 좌우 16px, radius 12px |
| 보조·아이콘 버튼 | min-height/min-width 44px |
| 검색 입력 | min-height 52px, 입력 글자 16px, radius 12px |
| 포커스 | 3px solid primary, offset 2px |
| 원형 버튼·배지 | 배지만 pill. 대부분의 카드·버튼은 12px 통일 |

| PC 4 | 내 자료 | `/library/` |
| PC 우측 | 로그인 / 내 계정 | 기존 인증 흐름 |
| 모바일 상단 | 로고 + 계정 + 메뉴 | 높이 56px, 각 동작 44px 이상 |
| 모바일 하단 | 문제 풀기 / 오답노트 / 내 자료 / 메뉴 | 비응시 화면, safe-area 반영 |

“스토어/문제은행” 양자 전환은 통합 메뉴로 대체한다. “스토어”와 “요약노트”를 같은 위치의 별도 메뉴로 반복하지 않는다. CBT MATE는 문제은행 기능명으로 유지할 수 있으나 로고가 바뀌며 다른 사이트처럼 보이지 않게 한다.

### 히어로 카피 세 안

| 안 | 한 문장 | 선택 이유 |
|---|---|---|
| 1 권장 | **내 시험 기출부터, 틀린 문제 복습까지.** | 시험 선택과 오답 복습이 함께 드러남 |
| 2 | 기출을 풀고, 내 약점을 다시 확인하세요. | 기존 CBT 카피와 연결하기 쉬움 |
| 3 | 문제로 점검하고, 핵심노트로 정리하세요. | 학습→노트 흐름 강조; 구매가 우선으로 읽히지 않도록 검색을 더 크게 배치 |

“한 줄 카피”는 한 문장이라는 뜻이다. 360px에서 억지로 한 줄에 넣거나 글자를 줄이지 않고 두 줄을 허용한다. “로그인 없이 무료”는 실제 비회원 경로·제공 범위를 검증한 뒤 별도 13px 안내로 사용한다. AI 해설 무제한·전 기능 무료·합격 보장은 표시하지 않는다.

### NAS 지연 구간 UX

| 상태 | 시간·표현 | 구현 기준 |
|---|---|---|
| 홈·메뉴·검색 쉘 | 즉시 표시 | NAS·인증·가격 응답을 전체 렌더링 조건으로 사용하지 않음 |
| 검색 카탈로그 갱신 | 기존 확인된 목록 유지; 실패 안내는 검색 영역 안에만 | 목록·수치의 release/갱신 정보를 관리. 응답 없을 때 가짜 목록 금지 |
| 실제 문제 번들 요청 | 300ms 미만이면 스피너 표시 안 함 | 질문 콘텐츠 영역만 대기; 주변 탐색은 유지 |
| 300ms 이후 | 스피너 24px + “시험지를 준비하고 있어요” | 실제 로그인 표시 이름이 확인됐을 때만 “OOO님의 시험지를 준비하고 있어요” |
| 회전 안내 | 5초마다; 최소 높이 48px 예약 | “선택한 문제를 불러오고 있어요” 등 사실 기반 문구. 가짜 진행률 금지 |
| 15초 이후 | “평소보다 오래 걸리고 있어요.” | 취소/다시 시도 44px; 기존 AbortController·중복 요청 병합 유지 |
| 실패 | 오류 + 다시 시도 | 재시도 중 중복 시험 기록 생성 금지. 기존 요청 수명주기 보존 |
| 접근성 | `role=status`, `aria-live=polite`, `aria-busy` | 변화는 문장 교체 시에만 읽기. reduced-motion이면 회전·fade 정지 |

기존 로컬 코드의 300ms / 5초 / 15초와 요청 취소 기능을 재사용한다. 목표는 애니메이션을 추가하는 것이 아니라 **로딩 적용 범위를 문제 콘텐츠로 좁히는 것**이다. 프레임·검색은 보이고 문항만 기다리게 한다.

## C 효과 대비 우선순위

공수는 기존 컴포넌트 재사용을 전제로 한 추정이며, 실측 작업 기간이 아니다.

| 순위 | 작업 | 예상 공수 | 기대 효과 |
|---:|---|---|---|
| 1 | 학습 홈 + 자격증 검색/바로가기 + 스토어 `/store/` 이동 + 홈 쉘 독립 | 1~2일 | 방문 목적과 첫 행동 일치. 아래 구현 프롬프트의 묶음 |
| 2 | 메뉴 통합·라벨 정리, 모바일 상단/하단 배치 | 0.5~1일 | 탐색 우회·브랜드 분절 감소 |
| 3 | 대비·타이포·터치 토큰 통일, 기존 취약 버튼 수정 | 0.5~1일 | 전 화면 읽기·터치 개선 |
| 4 | 실제 종목 목록 1열 압축, 중복 분류 라벨 제거 | 0.5일 | 긴 목록 스캔 개선 |
| 5 | 문제 로딩 영역 국소화, 취소/재시도·레이아웃 예약 | 1일 | NAS 지연에도 화면 사용 가능 |
| 6 | 무료/로그인/기록/AI 해설 범위 명확히 표시 | 0.5일 + 범위 확인 | 기대 불일치 감소; 숫자 통계 대신 사실로 신뢰 형성 |
| 7 | 결과·오답 아래 실제 종목 매핑 노트 링크 | 0.5~1일 | 학습 이유가 있는 상품 연결 |
| 8 | 기존 기록 “이어서 풀기” + 목록 노출 순서 개선 | 1일 | 반복 방문 첫 행동 단축 |
| 9 | FAQ·출처/수록 범위·오류 신고·갱신 안내 | 0.5~1일 + 검수 | 콘텐츠 신뢰 보강 |
| 10 | 소규모 사용성 검사 후 첫 문항 도달·재풀이 측정 | 0.5~1일 | 디자인 가설을 사용자 행동으로 검증 |

1~2일에는 1순위 묶음을 우선 완료한다. 2~10순위와 단원별 추천 엔진까지 동시에 넣지 않는다. 초기 지표는 방문→자격증 선택→시험 시작→첫 문항 표시→오답 재풀이이며 결제 전환은 후순위다. 현재 트래픽이 없으므로 먼저 수험생 3~5명의 과업 검사로 막히는 위치를 확인한다.

## D 1순위 묶음 구현 프롬프트

다음 지시문은 코드 적용용이다. **이번 요청에서는 문서만 작성했다.** 전면 재설계 제안이 이전의 데스크톱 보존 조건을 자동 해제하는 것은 아니다. 이후 구현 시 홈·공통 헤더의 PC 재설계를 허용할 범위를 명시하고 적용한다.

## 적용 전에 확인할 항목

| 항목 | 현재 결론 |
|---|---|
| 실제 사용자 첫 행동·이탈 | 데이터 없음. 가설 검증 필요 |
| 모두CBT 모바일 배치/타이포/터치 치수 | 스크린샷으로 확인 필요 |

새 서비스 UI, 운영 설정, DB, 배포는 이번 진단에서 변경하지 않았다. 이 문서는 구현 제안이며 사용자 테스트로 검증된 전환 개선 수치를 주장하지 않는다.
