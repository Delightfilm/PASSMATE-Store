## Slow 3G 8케이스

Chrome DevTools → Network → Preserve log / Disable cache → Slow 3G. 프리셋이 없으면 download/upload 500 kbit/s, latency 400 ms의 별도 QA 프로필. 가상 문항·QA 계정만 사용하고 토큰은 캡처/공유하지 않는다.

| # | 조작 | 기대 결과 |
|---|---|---|
| 1 | 같은 문항 1→2→3→4 연타 | 즉시 UI 반영, 그 문항 요청 직렬화, DB 최종 ④ |
| 2 | 앞 요청 응답 전에 다른 문항 이동·선택 | 이동·선택 가능, 다른 문항 큐는 병렬, 답이 섞이지 않음 |
| 3 | 이동 중 특정 답 저장 요청 실패 | 실패 문항만 이전 확정 선택으로 복귀·오류 토스트; 현재 문항 유지 |
| 4 | 뒤 선택 후 앞 요청의 늦은 ACK | 뒤 선택 UI를 덮어쓰지 않음; 마지막 선택이 최종값 |
| 5 | 서버 실패 후 재선택·정상 재시도 | 큐가 회복하고 마지막 선택이 DB에 저장됨 |
| 6 | 저장 대기 중 최종 제출 | 모든 문항 큐 완료 후 submit POST; 실패가 있으면 제출 중단 |
| 7 | 저장 대기 중 새로고침/다른 탭 조회 | 서버 확정 답으로 복원. 미확정 선택의 영속 재전송은 이번 구현 범위 아님; 데이터 보존 필요 시 새로고침은 저장 완료 후 |
| 8 | 두 탭에서 동시 최종 제출 | 응시 한 행·최초 답안/점수/제출 시각 유지, 오답 횟수 한 번만 증가 |

추가 시작 검증: 더블클릭, 응답 유실 뒤 동일 UUID 재시도(새로고침 포함), 서로 다른 UUID의 두 탭 동시 시작, 반환된 응시 만료/제출 후 키 재시도. 모두 같은 canonical client_id를 확인한다.

정상 중단: **신규 시작 플래그만 0**, 기존 응시가 끝날 때까지 허용 목록·서버 키·DB true 유지. DB false/행 제거는 저장·제출까지 막는 비상 정지다. 구성표 변경은 앱 service_role로 하지 않는다.
