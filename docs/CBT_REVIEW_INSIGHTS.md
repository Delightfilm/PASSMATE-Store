# CBT review, private notes and response statistics

Owner request (2026-10-05): make live answer feedback, AI explanations and answer-sheet guidance easier to scan; add personal notes below explanations and collect question response rates including guests.

## Reading and notes

Live feedback uses a white card, a concise answer header, green correct choices and rose selected wrong choices with explicit text labels. AI content separates a main explanation from the four choice reasons. Correct and selected wrong reasons share the same colors as the answer choices. Keep the exact AI inaccuracy notice and existing answer-safety gates, prefetch and loading behavior. The answer-sheet legend uses labeled dots for selected answer, current question, correct and wrong.

Every live question has a private `나의 메모` editor below its choices/feedback, even before answering or in submit-grading mode. Result details and the wrong-note dialog share the same editor (2,000 characters, explicit save). The editor starts collapsed and opens on demand; the action uses an SVG chevron with fixed dimensions. Saving before answering neither grades nor locks the question and does not mark it reviewed. Reuse `wrongNotes.memo`, the local browser store and existing account-scoped tables/RLS. Memo-only records have zero wrong count and are excluded from wrong-note lists, wrong-question pools and account wrong totals; cloud reads retain these memos. Guests retain notes in this browser; logged-in changes use existing account synchronization. This does not publish notes or send them to the AI/statistics backend. Instant grading records personal wrong notes immediately. `reviewedQuestionIds` on each attempt prevents final submission from counting the same personal error twice; retries clear this list. Existing attempts without it retain the prior finalization behavior.

Response statistics leave a clear gap from the subject chip. The percentage and its description share one colored badge; response counts remain below it. There is no low-sample annotation or loading/unavailable copy. Prefetch the current exam's 100-question window and reuse a bounded browser-memory cache keyed by the full question revision. Revalidate values older than 60 seconds in the background while continuing to display their last real aggregate. Concurrent lookups share pending requests; successful response recording updates the cache immediately. Question navigation uses already loaded values without waiting for another request.

## First-response statistics

- Collect only selected answers: instant grading records the locked answer; submit grading records final answers after submission. Unanswered questions are excluded. Lookup and failed collection never block answering or submitting.
- Same-origin Next endpoint `/api/cbt/question-stats/` validates question identifiers and revision syntax. Read requests only look up public aggregate counts for those references/revisions, without reloading source questions. Record requests fetch trusted source questions with fresh corrections and compute correctness; browser correctness/answer keys are never accepted. The revision includes effective stem, choices, images, answer and source hash, isolating statistics after corrections.
- A signed HttpOnly, SameSite guest cookie is used for both guests and logged-in browsers. Store a salted visitor hash, question reference/revision and correctness only. No account/email, IP, device fingerprint, memo, raw question text or selected-answer text is stored in the statistics tables.
- One first response per browser/question/revision. Atomic inserts and aggregate updates make retries and concurrent writes idempotent. Bound write batches to 100 and a visitor to 3,000 new samples/day. Clearing cookies or using another browser can create another identity; this is a browser-response count, not a verified unique-person count or a foolproof anti-bot system.
- Display actual correctness percent and `응답 N개 중 M개 오답`. At zero responses show a neutral collection state. Based on the displayed percentage: >=70% blue `많이 맞히는 문제예요`, >=50% and <70% green `대체로 잘 맞혀요`, >=40% and <50% yellow `많이 헷갈려하는 문제예요`, <40% red `많이 틀리는 문제예요`. These describe current recorded responses, not a verified measure of confusion. No historical backfill or synthetic production samples are seeded.
- The Edge backend `question-bank-stats` implements custom server-token authentication before reading/writing responses. JWT verification is off because guest requests reach it only through the Next proxy; direct calls without the private token return 401. `PASSMATE_CBT_STATS_TOKEN` is sensitive and server-only in Vercel. Supabase stores only its SHA-256 verifier in a private RLS table. The existing pinned modern-key adapter supplies the admin context; no legacy service-role key is added to Vercel.
- All three statistics tables have RLS and deny anon/authenticated reads/writes; the atomic invoker RPC is callable only by service_role. Public browsers receive only aggregate counts. The security advisor's INFO `RLS Enabled No Policy` is intentional for these server-only tables ([advisor documentation](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)). Existing unrelated policies/advisories remain untouched.
