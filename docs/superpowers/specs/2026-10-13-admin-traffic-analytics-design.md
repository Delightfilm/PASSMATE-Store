# PASSMATE 방문 분석 관리자 대시보드 설계

- 작성일: 2026-10-13
- 상태: GA4 + PASSMATE 관리자 방식 승인, 이 문서의 검토 대기
- 기준 코드: `15910eff38cc2a447ed78dca5f064b531815443d`
- 작업 브랜치: `codex/admin-traffic-analytics`

## 목적과 현재 상태

검색 노출이 실제 방문과 학습으로 이어지는지 관리자가 확인한다. 어디서 유입됐는지, 처음 방문한 페이지와 인기 종목은 무엇인지, 실제 이용 시간과 문제풀이 시작·완료가 어떻게 달라지는지 기간별로 비교한다.

현재 앱에는 GA4 태그나 방문 분석 수집 코드가 없다. 기존 CBT 문항 통계는 방문 분석과 별개이며 그대로 유지한다. Vercel 프로젝트에 분석 관련 ID는 존재하지만, 앱의 수집 코드나 실제 방문 데이터가 확인된 상태는 아니다. 측정 시작 전의 방문·체류 기록을 새 기능으로 복원할 수 없다.

사용자는 GA4로 수집하고 PASSMATE 관리자에서 조회하는 방식을 선택했다. 새 Google 계정 접근 권한, 서비스 약관 동의, 유료 서비스는 이 설계 승인에 포함되지 않는다. 실제 연결 시 필요한 절차를 별도로 확인한다.

## 이번 구현 범위

1. 기존 관리자에 **방문 분석** 메뉴를 추가한다.
2. 공개 페이지 방문과 안전하게 정의한 학습·가입 이벤트를 GA4에 기록한다.
3. 서버가 GA4 Data API의 집계 보고서를 읽어 관리자에게 제공한다.
4. 연결되지 않았거나 아직 데이터가 없을 때도 원인을 구분해 표시한다.
5. Google Search Console과 네이버 Search Advisor의 기존 보고서로 이동할 수 있도록 연결 안내를 제공한다.

Search Console 검색어·노출·클릭을 관리자 내부에서 자동 조회하는 통합은 후속 범위다. 이번 핵심 대시보드는 Search Console 연결 없이도 동작한다. 정확한 네이버 검색어 수집 API가 있다는 전제로 구현하지 않는다.

세션 녹화, 키 입력 기록, 개인 회원별 행동 이력, 정밀 위치 추적, 광고 구매, 유료 분석 상품, BigQuery 도입은 포함하지 않는다. 기존 결제·스토어·NAS·AI 해설·문항 통계 수집 계약도 변경하지 않는다.

## 관리자 화면

기존 관리자 권한과 디자인을 유지하고 방문 분석 패널을 별도 컴포넌트로 만든다. 메뉴 선택 때만 보고서를 요청하여 상품·주문 관리 초기 로딩에 부담을 주지 않는다. 모바일에서는 차트와 표를 세로로 배치하고 표의 상세 행을 펼쳐 볼 수 있게 한다.

| 영역 | 표시 내용 | 운영에 쓰는 방법 |
| --- | --- | --- |
| 요약 | 방문자, 세션, 페이지 조회, 세션당 평균 참여 시간, 풀이 시작·완료 이벤트 수 | 방문 증가가 실제 학습 이용으로 이어지는지 확인 |
| 추이 | 날짜별 세션·풀이 시작 추이, 직전 동일 길이 기간 대비 증감 | 검색 노출·콘텐츠 개선 전후 비교 |
| 유입 | 채널, 세션 소스/매체, 캠페인별 세션·참여 시간·풀이 시작 | Google·네이버·직접 방문·SNS 등 비교 |
| 페이지·종목 | 랜딩 페이지, 인기 페이지, 종목별 방문·학습 이벤트 | 전기기능사·지게차·무대 종목의 개선 우선순위 판단 |
| 방문 환경 | 국가·도시, 기기, 브라우저별 집계 | 모바일 이용 환경과 유입 분포 확인 |
| 최근 방문 | 최근 30분 활성 사용자 | 최근 유입의 대략적인 규모 확인 |
| 측정 상태 | 연결 상태, 조회 시각, 보고서 지연·필터 적용 범위 | 숫자의 의미와 누락 가능성 이해 |

기본 기간은 최근 30일, 선택은 7일·30일·90일 및 직접 지정이다. 날짜와 집계 기준은 GA4 속성의 시간대에 맞추고 화면에 표시한다. 오늘 데이터는 갱신 중임을 표시하며 기간 비교의 당일 불완전성도 알린다.

소스·종목·기기 필터를 지원하되 각 보고서가 지원하는 조합만 제공한다. 실시간 영역은 기간 필터를 적용하지 않으며 적용 불가능한 필터를 명시한다. 여러 지표를 한 축에 무리하게 겹치지 않는다. CSV 내보내기는 관리자에게 표시한 집계만 포함하고 수식으로 해석될 수 있는 셀을 안전하게 처리한다.

## 지표 정의와 해석

| 지표 | 정의·주의점 |
| --- | --- |
| 방문자 | 선택한 기간·필터의 GA4 `totalUsers`. 개별 페이지의 방문자 수를 더해 사이트 방문자로 표시하지 않는다. |
| 세션 | GA4 `sessions`. 한 사람이 여러 번 방문하면 여러 세션이 될 수 있다. |
| 페이지 조회 | `screenPageViews`. 동일 페이지 재방문을 포함한다. |
| 세션당 평균 참여 시간 | 같은 기간·필터의 `userEngagementDuration / sessions`. 세션이 없으면 값 없음으로 표시한다. |
| 페이지 참여 시간 | 해당 페이지의 참여 시간 집계를 표시하고 전체 세션 지표와 분모를 혼동하지 않는다. |
| 풀이 시작·완료 | 해당 이벤트 발생 횟수. 한 세션에서 여러 번 풀 수 있다. |
| 학습 단계 비교 | 종목 보기·풀이 시작·완료의 이벤트 횟수 또는 명시한 집계 기준을 비교한다. 순서가 검증된 전환 퍼널로 표시하지 않는다. |
| 가입 | 실제 가입 성공이 확인된 경우의 `sign_up`. 로그인이나 버튼 클릭을 가입으로 세지 않는다. |
| 최근 30분 활성 사용자 | GA4 실시간 `activeUsers`. 동시에 접속 중인 정확한 인원이라는 표현은 사용하지 않는다. |
| 위치 | GA4가 제공하는 국가·도시의 대략적인 집계. GPS나 개인별 위치가 아니다. |

참여 시간은 페이지가 포커스되거나 앱이 전면에 있는 실제 이용 시간을 기반으로 한다. 종료 이벤트가 전달되지 않는 등의 사유로 누락될 수 있다. GA4의 방문자 수는 동의·브라우저·기기·광고 차단 설정의 영향을 받으며 개인별 실명 방문 기록과 동일하지 않다.

유입 표는 **세션** 소스/매체를 기본으로 사용한다. Google·네이버 등의 분류는 실제 소스 값으로 결정한다. 알 수 없는 유입을 추측해서 검색 유입으로 만들지 않는다. 첫 방문자 유입 정보와 세션 유입 정보를 같은 열에 섞지 않는다.

## 수집 이벤트와 안전한 데이터

| 이벤트 | 발생 조건 | 허용 정보 |
| --- | --- | --- |
| `page_view` | 동의한 방문자의 공개 경로 진입·SPA 이동 시 1회 | 정제한 공개 URL, 고정 페이지명, 안전한 외부 유입 정보 |
| `qualification_view` | 공개 종목 소개 화면이 실제 표시될 때 | 종목 식별자·분야·급수 등 공개 카탈로그 값 |
| `exam_start` | 새 문제풀이가 실제 시작될 때 | 종목 식별자, 공개 풀이 방식, 문항 수 구간 |
| `exam_complete` | 해당 풀이가 정상 완료되고 결과 화면에 도달할 때 | 종목 식별자, 공개 풀이 방식, 문항 수 구간 |
| `sign_up` | 새 회원 가입 성공을 확인할 수 있을 때 | 가입 방식의 고정 분류 |

이벤트 허용 목록과 파라미터 스키마를 공통 모듈로 제한한다. 풀이 시작·완료는 실제 흐름의 성공 지점에 연결하며 렌더링 반복·재시도로 중복되지 않게 한다. 서버에서 가입 여부를 구분할 수 없는 로그인 흐름은 `sign_up`을 보내지 않는다. 기존 데이터 구조로 확실히 확인할 수 없는 이벤트는 수집 상태에 미지원으로 표시한다.

GA4의 표준 참여 시간 측정을 활용하고 별도의 탭 체류 타이머로 중복 집계하지 않는다. 종목·학습 방식은 GA4 이벤트 범위 커스텀 정의로 등록한다. 새 커스텀 정의는 등록 전 기록을 소급 복원할 수 없으므로 연결 체크리스트와 측정 시작일에 반영한다.

이름, 이메일, 회원 식별자, `user_id`, IP, 계정 토큰, 메모, 문항 본문, 선택 답안, 원점수, 개별 시험 시도 ID, 자유 입력값을 분석 이벤트에 넣지 않는다. GA4가 자체 사용하는 익명 식별 외에 기기 지문을 만들지 않는다.

관리자·인증 콜백·개인정보 화면·API 등 비공개 경로에서는 측정하지 않는다. 실제 공개 경로 목록을 코드에서 관리한다. 임의 URL 전체를 허용하는 대신 공개 종목·문제은행 등 허용한 경로 형태만 기록한다. 페이지 제목 역시 회원 정보가 포함될 수 있는 브라우저 제목 대신 고정 공개 명칭을 사용한다.

URL의 일반 쿼리와 해시, 인증값을 제거한다. UTM은 허용한 항목의 길이·형식을 제한해 캠페인 분류용으로만 처리한다. 외부 리퍼러는 쿼리·해시·사용자 정보·민감한 경로를 제거하고 필요한 출처 도메인만 유지한다. 자동 페이지뷰·자동 SPA 이동 감지 및 불필요한 향상된 측정은 비활성화하고, 정제한 값으로 필요한 이벤트만 보낸다. 구현 검증에는 실제 전송 요청의 URL·파라미터 확인을 포함한다.

## 방문자의 선택과 측정 활성화

비필수 분석은 방문자의 동의 전에는 GA4 스크립트를 로드하거나 요청하지 않는 방식으로 설계한다. 허용·거절을 동등하게 제공하고 설정에서 변경할 수 있게 한다. 거절해도 문제풀이 등 사이트 기능은 정상 동작한다. 선택을 저장하는 최소 정보는 분석 데이터와 분리한다.

광고 기능, Google Signals, 광고 개인화는 웹 측정 코드에서 기본 비활성화다. 2026-10-14 사용자 결정에 따라 GA4 속성의 광고 지역 설정은 현재 값으로 유지하며 전역 광고 설정을 변경하지 않는다. PASSMATE 태그는 `allow_google_signals:false`, `allow_ad_personalization_signals:false`로 연결한다. 동의 철회 후에는 추가 이벤트 전송을 중단한다. 이를 과거 GA4 집계의 자동 삭제로 설명하지 않는다.

현재 전체 개인정보 처리방침이 완성됐다는 증거는 없다. 추정한 사업자 정보나 법적 문구를 게시하지 않는다. 분석 목적·제공 항목·보관 설정·선택 변경 방법의 실제 설정을 확인해 안내문 초안을 작성하고, 기존 개인정보 안내와 맞춘 뒤 측정을 활성화한다. 활성화 전까지 기능은 연결 안내 상태로 유지할 수 있다.

## 연결과 서버 구성

- GA4 기존 속성 유무를 먼저 확인하고 재사용 가능하면 재사용한다. 필요한 경우에만 새 속성을 만들며 속성 시간대는 운영 기준인 `Asia/Seoul`을 우선한다.
- 공개 측정 ID는 클라이언트 설정에 두고, GA4 속성 ID와 읽기 인증 정보는 서버 전용 환경변수로 관리한다. 인증 비밀은 브라우저·응답·로그·저장소에 노출하지 않는다.
- 조회용 서비스 계정은 해당 GA4 속성의 읽기 권한만 사용한다. 지속적인 자격 증명 생성·계정 접근 승인에 필요한 확인은 실제 연결 단계에서 진행한다. 불필요한 Google Cloud 프로젝트 관리자 권한을 요구하지 않는다.
- 기존 관리자용 Supabase Edge Function 패턴에 맞춰 독립된 보고서 함수와 공유 응답 타입을 둔다. 요청 JWT와 DB의 `profile.role = admin`을 검증한 뒤 GA4 API를 호출한다. 클라이언트가 지정한 임의 속성 ID나 API 보고서 본문을 그대로 실행하지 않는다.
- 기간·필터·허용 보고서 유형을 서버가 검증한다. 공개 방문자에게는 GA4 보고서 접근 권한이 없다. 기존 관리자 권한 범위도 확대하지 않는다.
- 동일 속성·기간·필터·보고서 버전의 일반 보고서는 최대 15분, 실시간은 최대 60초 캐시한다. 캐시 저장은 서버에서만 접근 가능한 작은 집계 캐시를 사용하고 사용자 원시 행동 로그는 저장하지 않는다. 중복 요청을 합치고 실시간 화면 자동 갱신은 60초보다 짧게 하지 않는다.
- GA4 차원·지표 호환성을 확인해 보고서를 나누어 조회한다. 지원하지 않는 필터 조합을 조용히 무시하지 않고 입력 단계에서 제한한다. API 할당량·권한 오류에는 무한 재시도하지 않는다.
- 캐시가 있으면 조회 실패 시 조회 시각과 함께 오래된 데이터임을 표시한다. 오래된 값은 최신 값으로 설명하지 않는다. 로그인 토큰은 캐시 키나 로그에 저장하지 않는다.

## 화면의 상태 구분

| 상태 | 화면 표현 |
| --- | --- |
| 연결 전 | 필요한 측정 ID·보고서 연결 단계 안내, 실제 숫자 없음 |
| 연결했으나 아직 수집 없음 | 측정 시작일·보고서 반영 대기 안내 |
| 정상 응답·실제 0 | 정상 조회된 기간의 0으로 표시 |
| 로딩 | 기존 데이터가 있으면 유지하고 갱신 표시 |
| 권한·할당량·네트워크 오류 | 원인 분류와 재시도 안내, 숫자를 0으로 대체하지 않음 |
| 오래된 캐시 | 마지막 성공 조회 시각과 갱신 실패 안내 |
| 개인정보 보호 등에 따른 제한 | GA4 응답의 임계값·기타 행·데이터 제한 정보를 해당 보고서에 표시 |

개발용 예시 데이터는 별도 테스트 환경에서만 사용한다. 운영 화면에 가짜 방문자·전환 수치를 채우지 않는다. 카드의 0, 미지원, 연결 전, 데이터 지연은 각각 구별한다.

## 검색 노출 확대에 활용

우선 전기기능사·지게차·무대음향·무대기계·무대조명 종목을 같은 기준으로 비교한다. 검색 유입 세션이 늘어도 학습 시작이 낮다면 해당 랜딩 페이지의 소개·종목 선택·풀이 진입을 개선한다. 검색 노출과 클릭률은 Search Console 보고서에서 함께 확인한다. 검색어를 개별 방문자의 정보로 연결하지 않는다.

이미 진행한 무대 1·2급 6개 페이지의 색인·수집 요청은 반복 제출하지 않는다. 등록 요청 완료와 실제 색인·검색 노출은 구분한다. 이후 콘텐츠 확장은 실제 수록 범위와 검증된 시험 정보에 맞춰 종목·급수·학습 의도별로 진행한다. 키워드를 숨겨 대량 삽입하거나 디자인을 해치는 반복 문구를 추가하지 않는다.

대시보드는 상위 노출을 보장하는 기능이 아니라, 유입과 학습 이용이 늘어나는 개선을 판단하는 도구다.

## 검증과 완료 기준

1. 동의 전·거절·비공개 경로에서 분석 요청이 발생하지 않는다. 철회 후 신규 요청이 중단된다.
2. 공개 SPA 이동 1회당 페이지뷰가 1회만 발생하고, 정제한 URL·리퍼러·허용 이벤트만 전송한다.
3. 풀이 시작·완료와 가입 성공 이벤트가 실제 성공 흐름에 맞고 새로고침·리렌더에서 중복되지 않는다. 기존 풀이·회원 기능은 통과한다.
4. 비로그인·일반 회원은 보고서 접근이 차단되고 관리자는 조회한다. 입력 검증·서버 비밀 보호·캐시 만료·오류 상태를 확인한다.
5. GA4 실제 속성 연결 후 DebugView/Realtime에서 테스트 동작을 확인하고 표준 보고서가 반영된 뒤 같은 기간·필터의 관리자 집계를 대조한다. 개발 이벤트는 운영 통계와 구분한다.
6. 모바일·데스크톱에서 기간·필터·빈 상태·오류·CSV·차트 접근성을 확인한다. 키보드와 그래프 대체 표로 지표를 읽을 수 있어야 한다.
7. 실제 GA4 연결이나 개인정보 안내 확정이 남으면 로컬 기능 검증과 운영 데이터 검증을 분리하여 보고한다. 연결 전 상태를 운영 분석 완료로 주장하지 않는다.

## 중단과 되돌리기

클라이언트 수집과 관리자 보고서 기능에 각각 비활성화 설정을 둔다. 문제 발생 시 먼저 수집을 중단하고 기존 관리자·CBT 기능은 유지한다. 코드 변경은 해당 변경 커밋을 되돌리고, 보고서 계정 접근은 GA4 속성에서 철회한다. 환경변수와 커스텀 정의 변경은 코드 되돌리기만으로 복구되지 않으므로 별도 적용 기록에 남긴다. 이미 GA4에 수집된 데이터는 코드 롤백으로 삭제되지 않는다.

## 구현 전에 확정·연결할 항목

- 이 문서 검토 후 구현 계획을 작성하고 검토받는다.
- GA4 기존 계정·속성 접근 여부, 측정 ID, 속성 시간대·보관 설정을 실제 화면에서 확인한다.
- 읽기 인증과 해당 속성 권한을 설정하고 커스텀 정의를 등록한다.
- 실제 앱 가입 성공 흐름의 이벤트 가능 여부를 확인한다.
- 분석 안내와 방문자 선택 UI를 확정한 뒤 수집을 활성화한다.

## 설계 자체 검토

작성자가 구현 전 범위·지표 분모·유입 기준·권한·개인정보·실시간 의미·빈 상태·롤백을 검토했다. 이벤트 횟수를 순차 전환율로 오인하는 표현, 페이지 방문자 합산, 연결 전 숫자 표시, 전체 URL 자동 전송을 배제했다. GA4 연결과 법적 안내 확정은 실제 검증이 필요한 외부 의존성으로 남겨 두었으며, 이를 완료한 것으로 취급하지 않는다.
