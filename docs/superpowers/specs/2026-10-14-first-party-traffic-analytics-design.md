# PASSMATE 자체 방문 집계 설계

작성일: 2026-10-14 (Asia/Seoul)

상태: 대화에서 선택한 구성을 문서화한 검토본. 제품 구현·운영 활성화 전이다. 사용자 서면 설계 검토 후 구현 계획을 작성한다.

## 1. 목적과 승인 범위

사용자는 자동 팝업과 하단 배너 없이 방문자·유입 경로·체류 시간을 법적으로 가능한 범위에서 최대한 정확하게 집계하기를 요청했다. 선택한 구성은 **자체 집계를 기본으로 제공하고 기존에 동의한 방문자의 GA4 보고서를 별도로 유지**하는 방식이다.

목표는 분석 동의값을 자동으로 `granted`로 기록하는 것이 아니라, 개인을 추적하는 식별자를 만들지 않고 공개 학습 화면의 이용량을 집계하는 것이다. 새로운 기본 집계는 Google에 전송하지 않는다. 기존 거절 선택은 존중한다. 학습 UI와 저장된 회원 응시·오답·북마크·주문 데이터는 보존한다.

구현 기준 저장소는 `Delightfilm/PASSMATE-Store`, 원격 main `b8c032895f66bde0363218d489be0cba1239b860`이다. 새 브랜치는 `codex/first-party-traffic-analytics`다. 이는 소스 기준이며 이 문서 작성으로 운영 동작이 변경된 것은 아니다.

## 2. 제공하는 지표와 한계

| 지표 | 정의 | 표시 시 주의점 |
| --- | --- | --- |
| 방문 시작 수 | 공개 페이지를 방문한 현재 문서·탭의 첫 진입, 또는 측정 가능한 활동이 30분 이상 끊긴 뒤 재진입 | 순방문자·고유 사용자 수로 부르지 않는다. 새 탭과 전체 새로고침은 다시 셀 수 있다. |
| 페이지 조회수 | 공개 화면을 처음 표시하거나 실제 공개 경로로 이동해 표시한 횟수 | React 재렌더링·포커스 복귀·bfcache 복귀만으로 같은 조회를 다시 세지 않는다. |
| 유입 분류 | 현재 문서 진입 시 확인 가능한 출처를 고정된 범주로 변환한 값 | 출처가 없으면 ‘직접/알 수 없음’이다. 이를 모두 직접 유입으로 단정하지 않는다. |
| 총 활성 화면 시간 | 공개 화면이 표시되고 문서가 포커스를 가진 동안 관측한 시간의 합 | 실제 사람이 읽거나 집중했다고 주장하지 않는다. |
| 조회당 활성 시간 | 같은 집계 기간에 수신된 총 활성 시간 / 페이지 조회수 | 평균의 정의를 고정한다. 조회수 0이면 ‘—’다. GA4 세션당 참여 시간과 동일한 지표가 아니다. |

쿠키·기기 식별자·사용자별 서버 상태 없이 여러 문서·탭·날짜에 걸쳐 같은 사람을 구별할 수는 없다. 순방문자와 재방문자 수, 개인별 이동 경로, 회원별 체류 시간은 기본 집계에서 제공하지 않는다. 나라·도시·기기·브라우저·검색어·자유 입력 캠페인 이름도 이번 기본 집계에 추가하지 않는다.

## 3. 수집 범위와 데이터 최소화

측정 화면은 메인, 전체 문제은행, 공개 카탈로그에 있는 종목, 종목의 일반 문제풀이 화면이다. 문제풀이 주소는 종목별 공통 키로 변환하며 회차·시도 ID와 쿼리·해시를 제외한다. 관리자·계정·인증 콜백·API·결제·오답 노트·북마크·개인 이력·설정/정책 화면은 측정하지 않는다.

브라우저는 공개 카탈로그 키, 고정 유입 분류, 증가분 카운터, 정수 활성 시간만 구성한다. 원본 URL·리퍼러를 서버에 보내지 않는다. 유입 분류는 네이버, 구글, 다음, 빙, 소셜, 기타 외부, 직접/알 수 없음으로 제한한다. 출처 문자열은 브라우저에서 분류한 뒤 버린다. 같은 문서의 SPA 이동은 최초 외부 유입 분류를 유지한다.

분석 저장소에는 IP, 회원 ID, 이메일, 이름, 인증값, 기기/브라우저 식별자, 전체 User-Agent, 개별 방문/세션 기록, 답안, 점수, 문항 내용을 저장하지 않는다. 기본 집계에 사람·탭·세션을 연결하는 ID를 만들지 않는다. 계정·응시 데이터와 조인하지 않는다.

## 4. 수집 경로

데이터 흐름은 다음과 같다.

1. 공개 화면의 브라우저 수집기가 메모리에서 증가분을 계산한다.
2. 같은 출처의 `POST /api/analytics/aggregate`로 제한된 집계 패킷을 전송한다.
3. Next.js 경로가 원점·크기·계약·수치·공개 카탈로그를 검증하고 집계값만 서버 요청으로 전달한다.
4. 전용 Supabase 수집 함수가 서버 전용 토큰을 검사하고 하나의 트랜잭션으로 일별 합계에 반영한다.
5. 별도 관리자 조회 함수가 JWT와 DB 관리자 role을 확인한 뒤 집계 보고서만 반환한다.

브라우저에서 Supabase 수집 함수로 직접 보내지 않는다. 원래 요청의 Cookie, Authorization, IP 전달 헤더, User-Agent, Referer를 후속 서버 요청에 복사하지 않는다. 서버 자격 증명은 보호된 서버 설정에만 둔다.

수집 요청은 `fetch`의 `credentials: omit`, `referrerPolicy: no-referrer`, 제한된 `keepalive`를 사용한다. Cookie를 포함할 수 있는 `sendBeacon`은 기본 전송으로 사용하지 않는다. 인증 헤더를 직접 구성하지 않는다. 응답은 수집 요청에 `Set-Cookie`를 설정하지 않는다.

기존 웹호스팅·보안 사업자가 HTTP 처리에 관여하는 사실과 분석 DB 저장 범위는 구분한다. 인프라가 IP를 전혀 처리하지 않는다고 주장하지 않는다. 앱의 수집 로그에는 요청 본문·원본 헤더·개별 주소를 기록하지 않는다. 기본 집계 목적의 원시 요청 복제·로그 저장은 금지하며 실제 운영 관측 설정을 활성화 전 점검한다.

## 5. 브라우저 집계 상태

방문 상태와 시간 누적은 현재 문서의 메모리에서만 유지한다. 기본 측정을 위한 쿠키, localStorage, sessionStorage, IndexedDB 값 또는 기기 지문을 생성하지 않는다. 사용자가 직접 변경한 측정 선택만 기능성 설정으로 저장한다.

공개 경로의 첫 표시에서 조회 1회와 방문 시작 1회를 기록한다. 같은 문서의 다른 공개 경로로 이동하면 조회만 1회 늘린다. 동일 경로 재렌더링은 제외한다. 비공개 화면에 머무는 시간은 누적하지 않으며 비공개 경로 자체를 보내지 않는다. 비공개 화면을 거쳐 공개 화면을 다시 표시하면 새로운 공개 조회로 계산한다. 30분의 측정 활동 중단 뒤 복귀하면 다음 공개 조회에 방문 시작 1회를 추가한다.

`performance.now()` 기반으로 경과 시간을 계산하고 `visibilitychange`, 포커스/블러, `pagehide`/`pageshow` 및 경로 변경에서 상태를 조정한다. 활성 타이머의 정상 측정 간격은 5초다. 연속 관측 사이 공백이 10초를 넘으면 확인되지 않은 공백을 활성 시간으로 추정해 더하지 않는다. 읽는 동안 입력이 없다는 이유만으로 시간을 중단하지는 않는다.

20초마다 증가분을 전송하며 숨김·블러·종료·공개 경로 변경 때 이전 화면의 미전송 시간도 정리한다. 이미 보낸 시간을 다시 보내지 않는다. bfcache 복귀는 기존 조회를 유지하고 활성 시간 측정만 재개한다. 한국 자정 부근의 집계일은 서버 수신일 기준이며, 네트워크 지연으로 실제 관측일과 차이가 날 수 있음을 운영 문서에 기록한다.

## 6. 전송 계약과 중복 방지

패킷은 버전, 일회성 패킷 nonce, 전체 합계 증가분, 유입별 증가분, 공개 페이지별 증가분으로 구성한다. nonce는 패킷마다 독립적으로 만들며 방문자·탭을 연결하는 값으로 재사용하지 않는다. 전송할 카운터는 생성 시 고정하며 재시도는 같은 패킷과 nonce를 사용한다.

집계값은 페이지 조회수·방문 시작 수·활성 밀리초인 비음수 정수다. 한 패킷은 최대 8KiB, 최대 20개의 공개 페이지 항목, 전체 조회수 최대 20, 방문 시작 수는 조회수 이하, 활성 시간은 최대 60초로 제한한다. 유입별 합과 페이지별 합은 각각 전체 합과 일치해야 한다. 임의 필드, 전체 주소, 원시 시간표, 카탈로그 외 키, 임의 출처, 과대/음수/비정수 값은 수집하지 않는다.

서버는 nonce의 해시와 만료 시각만 운영용 중복 방지 테이블에 둔다. 이 테이블에는 페이지·유입·증가분·방문자 정보가 없다. 유효기간은 30분이며, 클라이언트의 재시도 유효기간은 5분보다 길지 않다. 카운터 반영과 중복 방지 영수증 삽입은 같은 트랜잭션에서 처리한다. 같은 패킷을 동시 재전송해도 증가분은 한 번만 반영한다.

클라이언트는 동시 전송 1개, 미전송 공개 페이지 키 최대 20개, 5분 이내의 메모리 버퍼만 유지한다. 누적 증가분이 패킷의 한도를 넘으면 합계가 보존되도록 제한된 패킷으로 나누어 전송한다. 정상 화면에서 보낼 수 있는 패킷이 꽉 차면 먼저 전송한다. 버퍼 키/기간 한도를 초과한 값은 버리며 원시 기록을 저장해 복구하지 않는다. 전송 실패를 학습 오류로 표시하지 않으며, 저장소에 영구 오프라인 큐를 만들지 않는다. 종료 시 전송 성공과 전체 방문의 누락 없는 집계를 보장하지 않는다.

## 7. 저장 구조와 보관

자체 집계는 기존 GA4 캐시·회원 응시 테이블과 분리한다. 일별 집계의 키는 한국 수신일, 차원 종류, 차원 키다. 차원 종류는 전체, 유입, 공개 페이지이며 각각 별도의 주변 합계를 저장한다. 페이지×유입×시간×개인으로 교차하는 상세 레코드와 순서 로그는 만들지 않는다.

집계 카운터는 조회수, 방문 시작 수, 활성 밀리초다. 서버 측 측정 활성화 시각은 별도 메타데이터로 보존한다. 기본 보관 범위는 오늘을 포함한 최근 90일이다. 중복 방지 영수증은 30분 이후 재전송 판정에서 제외한다. 영수증의 물리적 삭제는 수집·조회 시 정리와 일일 유지관리로 수행해 만료 후 24시간 이내에 제거한다. 일별 집계도 일일 유지관리로 보관 범위를 정리한다.

운영 프로젝트 `fmecqeadghrdisirucqm`의 읽기 전용 확인에서 `pg_cron`은 사용 가능하지만 아직 설치되지 않았고 `pgcrypto`는 설치된 상태였다. 구현에서는 `pg_cron`을 활성화하고 한국 시간 매일 05:00에 새 집계표·영수증만 정리하는 작업을 등록한다. 기존 테이블·작업은 변경하지 않는다. 작업 실패 상태를 운영자에게 노출하고 정리 실행을 검증한 뒤 수집을 활성화한다. 이 문서 작성 단계에서는 확장 설치나 작업 등록을 실행하지 않았다.

집계/영수증/메타데이터 테이블에는 RLS와 명시적 권한 제한을 적용한다. `anon`과 일반 `authenticated`는 직접 읽기·쓰기·RPC를 할 수 없다. 공개 수집은 검증된 서버 경로와 전용 수집 함수만 사용한다. 조회는 검증된 관리자 함수만 사용한다. 서버 토큰은 새 집계 작성에만 쓰며 코드·브라우저·보고서에 노출하지 않는다.

## 8. 보안과 수집 품질

수집 경로는 동일 원점과 허용된 사이트 호스트를 확인하고 크기·형식 제한, 제한 시간, 과부하 중단을 적용한다. 배포 미리보기와 로컬 개발은 기본 비활성화하며 운영 테이블에 쓰지 않는다. 별도 검증용 수집 대상에서 테스트한 뒤 운영을 켠다.

기존 엣지 보안 기능을 유지하되, 분석을 위해 새로운 IP/브라우저 지문을 만들지 않는다. 동일 원점 확인만으로 봇·조작 요청을 모두 차단했다고 주장하지 않는다. 검증된 사람 수라는 지표는 제공하지 않는다. 비정상 트래픽 대응은 공급자 보안 계층과 서버 용량 제한으로 처리하고 집계 오염·누락 가능성을 운영 품질 한계로 기록한다.

## 9. 기존 선택과 GA4의 관계

| 상태 | 자체 집계 | GA4 |
| --- | --- | --- |
| 아직 선택하지 않은 신규 방문자 | 기본 활성 | 비활성 |
| 기존 GA4 허용, 새 중지 선택 없음 | 활성 | 기존 설정대로 활성 |
| 기존 GA4 거절, 새 선택 없음 | 비활성 | 비활성 |
| 사용자가 새 설정에서 ‘모두 중지’ | 비활성 | 비활성 |
| 사용자가 ‘기본 집계만 사용’ | 활성 | 비활성 |
| 사용자가 안내를 확인하고 ‘상세 분석도 허용’ | 활성 | 명시적 허용 이후 활성 |

기존 거절을 새로운 기본값으로 덮어쓰지 않는다. 저장된 명시적 새 기본 선택은 자체 집계에 적용하며 GA4 허용과 구분한다. 기본 집계만 재개하는 조작은 예전 GA4 허용을 자동 복원하지 않는다. GPC가 활성화된 브라우저에서는 두 수집기를 모두 중단하며, 선택 저장이 불가능해도 학습 기능은 유지한다.

GA4 수집 조건·서버 보고서·보관 데이터는 보존한다. 새 기본 집계 값을 Google에 복제하지 않는다. 자체 집계와 GA4는 같은 사람이나 페이지를 포함할 수 있으므로 방문자·조회수·체류 시간을 서로 합산하지 않는다. 자체 집계의 도입 전 과거 기간을 GA4에서 복사해 채우지 않는다.

## 10. 방문자 설정과 공개 안내

자동 팝업·하단 동의 배너를 제거한다. 푸터 ‘분석 설정’은 독립된 안내/설정 페이지로 이동하는 링크로 바꾸어 수동 조작에서도 팝업을 쓰지 않는다. 이 화면은 검색 색인에서 제외한다.

설정 화면에는 기본 집계의 항목·목적·보관 기간·처리 구조·측정 중지 방법과, 선택적으로 허용한 GA4의 기존 정보를 정확히 설명한다. ‘모두 중지’, ‘기본 집계만 사용’, 명시적인 ‘상세 분석도 허용’을 제공한다. 사용자에게 접속만으로 동의했다고 설명하지 않는다. 바뀐 선택은 다른 열린 탭에도 반영하고 중지 시 대기 중인 모든 측정 데이터를 폐기한다.

공개 안내는 실제 구현 범위에 한정한다. 미완료된 전체 개인정보 처리방침을 완성된 법률 문서처럼 꾸미지 않는다. 기존 호스팅·회원 정보의 처리와 새 기본 통계의 저장을 구분한다.

## 11. 관리자 화면과 조회 API

기존 ‘방문 분석’에 ‘자체 기본 집계’와 ‘GA4 동의자 분석’ 출처를 구분해 제공한다. 기본 선택은 자체 집계다. 자체 화면은 요약, 일별 추이, 유입 분류, 인기 공개 페이지, 7·30·90일/직접 기간, CSV를 제공한다. 기존 색·카드·표 스타일을 재사용한다. 회원 ‘인기 시험’ 시트는 현재 기준 그대로 둔다.

자체 조회 API는 서버가 기간과 차원을 검증하고 최근 90일 이내만 읽는다. 날짜·유입·페이지를 교차해 개별 행동을 좁히는 필터는 제공하지 않는다. 유입·페이지 항목에서 기간 내 조회가 5회 미만인 항목은 ‘소량 항목’으로 합쳐 표시하며, 이것을 5명의 사람이 방문했다는 익명성 보증으로 해석하지 않는다. 조회 표는 상위 100행, 전체 합계는 별도로 조회하며 상위 행의 합계를 전체로 표시하지 않는다. 평균은 총 활성 시간/총 조회수로 가중 계산한다.

조회 응답에는 출처, 시간대, 측정 시작 시각, 수집일 기준, 오늘 미완료 여부, 조회 시각, 행 제한을 포함한다. 측정 시작 전 구간은 ‘측정 전’으로, 비활성 설정은 ‘연결 전’으로, 조회 실패는 오류로 표시한다. 이들을 방문자 0명으로 바꾸지 않는다. 캐시를 쓰면 마지막 성공 시각과 실패를 보여주며 운영 집계의 실시간성을 과장하지 않는다. CSV에도 같은 정의·범위·출처·제한을 기록한다.

## 12. 출시 검증 기준

- 계약 검사: 허용 키·유입 분류·수치 한계·크기·합계 불일치·알 수 없는 필드·중복 패킷을 검증한다.
- 수집기 검사: SPA 이동, 동일 경로 재렌더링, 비공개 전환, 30분 단절, 숨김/블러, bfcache, 중지 경합, 재시도에서 중복과 시간 과대 계상이 없다.
- 프라이버시 검사: 신규/거절/GPC/기존 허용 상태별 요청을 캡처해 Cookie·Authorization·Referer·민감 필드·자동 GA4 호출 여부를 대조한다. 테스트는 격리된 대상에서 수행한다.
- 저장 검사: 집계표에 개인/방문 기록이 없고 영수증에 페이로드가 없으며, 중복 반영·동시 증가분·만료 정리가 올바르다.
- 접근 검사: 비로그인·일반 회원의 직접 DB/API 조회가 실패하고 관리자만 보고서를 읽는다.
- 보고서 검사: 전체/주변 합계, 가중 평균, 시작일 이전·빈 결과·오류·오늘·상위 행·CSV 범위가 일치한다.
- 실제 브라우저: 초기 화면과 이동에서 자동 팝업/배너가 없고 학습 UI가 유지된다. 설정 페이지의 선택·다른 탭 반영·모바일·키보드 접근을 확인한다.
- 배포 검사: 원격 main 커밋, 운영 배포 ID/별칭/공개 플래그, 실제 패킷→집계→관리자 숫자의 연결을 확인한다. 로컬 검사를 운영 성공으로 기록하지 않는다.

집계 저장 전후와 인프라 로그 설정을 대조한 결과가 데이터 최소화 요구를 충족하지 않으면 해당 수집 플래그를 켜지 않는다. 단순히 이름·이메일이 없다는 이유로 법적 익명성을 단정하지 않는다.

## 13. 활성화와 롤백

자체 수집·조회는 기존 GA4 플래그와 독립적인 설정으로 제어한다. 보호된 서버 설정에는 전용 수집 토큰을, 브라우저에는 비밀이 아닌 활성화 플래그만 둔다. 기본값은 비활성이다. 검증된 운영 서버 연결·집계 유지관리·공개 안내를 함께 반영한 뒤 새 기본 측정을 활성화한다.

롤백은 자체 수집과 조회 플래그를 끄고 검증된 이전 웹 배포를 되돌리는 순서다. 기존 GA4 동의 선택·분석 데이터·회원 응시·학습·주문 데이터를 삭제하지 않는다. 새로운 집계 테이블은 보관 정책에 따라 유지하며 자동으로 과거 데이터를 지우는 조작을 롤백에 포함하지 않는다. 중단 후 정책상 필요한 정리는 별도 범위로 처리한다.
