# PASSMATE 학습 홈 1단계 변경 계획

2026-10-05 · 코드 적용 전 검토용 · 기존 CBT_UX_REDESIGN_PROPOSAL.md의 D 지시문을 이 문서로 대체

**루트 홈을 검색 중심 학습 홈으로 바꾸고, 현재 상품 홈을 `/store/`에 보존한다.** 검색 데이터는 공개 카탈로그에서 빌드 시 자동 생성한다. 홈 요청은 NAS·가격 응답을 기다리지 않는다. 이 문서는 계획이며 애플리케이션 코드는 아직 변경하지 않았다.

## 확정 범위

| 구분 | 이번 작업 |
|---|---|
| 학습 홈 | `/` 제목·자격증 검색·“바로 풀 자격증”·상시 스토어 링크 |
| 검색·바로가기 | 실제 catalog에서 생성한 전체 종목 목록으로 검색; 기존 종목 상세로 연결 |
| 스토어 이동 | 기존 홈의 상품·가격·CTA·학습 순서를 `/store/`로 이동 |
| 즉시 표시 | 서버 HTML에 홈 쉘과 검색 초기 데이터 포함. NAS·가격·인증 확인 때문에 전체를 숨기지 않음 |
| PC | 홈과 공통 헤더의 필요한 변경 허용. 이번에는 헤더 URL·활성 상태·관련 표시만 수정 |
| 헤더 | 기존 메뉴·서비스 전환 구조 유지. 스토어 목적지를 `/store/`로 바꾸고 루트의 활성 상태 보정 |
| 푸터 | 하단에 **딜라이트 커머스 · 사업자등록번호 876-59-00934** 표시. 약관·환불정책은 실제 URL 확인 후 연결. 모바일에서도 숨기지 않음 |
| 보조 텍스트 | 학습 홈·이전된 스토어 홈·해당 헤더/푸터의 UI 보조 텍스트 최소 **14px** |
| 보존 | 기존 인증·결제·SKU 가격 검증·권한·다운로드·시험 생성/채점/저장 계약 |
| 제외 | 메뉴 통합, 하단 탭, 토큰 전면 개편, 오답 후 노트 연결, 이어풀기 |
| 운영 | 운영 배포·운영 DB 쓰기·실결제 없음 |

요약: 사용자가 PC 변경을 허용했지만, 2단계 항목을 이번에 끼워 넣지 않는다. 기존 상세·장바구니·결제·내 자료를 새로 디자인하지 않는다. 표지 인쇄 글자는 UI 보조 텍스트와 구분하고 표지 자체를 재제작하지 않는다.

## 화면과 경로

```text
/ 학습 홈
  기존 헤더 구조                  스토어 링크 → /store/
  내 시험 기출부터, 틀린 문제 복습까지.
  [자격증 이름 검색_______________]   입력 16px / 높이 52px
  바로 풀 자격증
  [실제 종목 1] [실제 종목 2]         각 터치 44px 이상
  [실제 종목 3] [실제 종목 4]
  [전체 자격증 보기] → /cbt/
  [핵심노트 스토어] → /store/         항상 표시, 메뉴 안에만 넣지 않음
  푸터: 딜라이트 커머스 · 사업자등록번호 876-59-00934
        이용약관 / 환불정책은 실제 URL 확인 후 연결

/store/ 상품 홈
  현재 /의 HomeProducts + 상품 비교 + 학습 순서
  기존 서버 가격·skeleton·실패 재시도·상품 상세 연결 보존

/cbt/, /cbt/{기존 종목 slug}/, /products/, /products/{slug}/,
/cart/, /checkout/, /library/, /account/…
  기존 URL과 계약 유지
```

홈에서 검색 결과/바로가기를 누르면 기존 종목 상세로 이동한다. 검색만으로 시험 기록을 생성하거나 바로 응시를 시작하지 않는다. 루트의 로고와 기존 CBT 로고의 홈 연결은 각각 현재 의미를 유지하며, 모든 스토어 홈 진입 링크는 `/store/`로 연결한다.

`components/question-bank-client.tsx`, `lib/question-bank-content.ts`, `lib/question-bank-download.ts`와 인증·결제·다운로드 처리 파일은 원칙적으로 수정하지 않는다. 검색의 기존 규칙은 먼저 조사한 뒤 순수 helper로 구현하며 대형 CBT 컴포넌트를 홈에 통째로 넣지 않는다.

현재 `certSlug`는 명시 slug가 없으면 **title의 공백을 하이픈으로 바꾼 값**을 사용한다. snapshot의 code를 URL slug라고 가정하지 않고 현재 규칙과 같은 결과인지 테스트한다. 종목 식별은 원본 code를 유지한다.

## catalog snapshot 정책

| 항목 | 계획 |
|---|---|
| 입력 | 기존 공개 content URL의 `/catalog.json`. env 파일 값을 출력하거나 비공개 토큰을 넣지 않음 |
| 생성 시점 | Next production build config 단계. 명시적 `npm run catalog:snapshot`도 제공 |
| 조회 범위 | catalog 한 개만 읽음. 문제/이미지 번들 다운로드 안 함 |
| 제한 | 요청 timeout 5초, 최대 1회 재시도, 재시도 전 1초. 전체 대기 약 11초 이내 |
| 검증 | schemaVersion·비어 있지 않은 releaseId·종목 code/title·중복 code/경로·문항/회차 정수 확인 |
| 출력 | `snapshotSchemaVersion`, `releaseId`, `generatedAt`, `sourceSha256`, `qualifications` |
| 원본 대응 | 전체 종목 목록은 원본에서 자동 변환. 출시 회차·문항 수를 생성하지 않음 |
| 바로가기 | 유효 회차/문제가 있는 실제 종목을 안정 정렬해 최대 6개. “인기”라고 표시하지 않음 |
| 쓰기 | 임시 파일에 완전히 기록·검증 후 교체. 실패 시 기존 파일을 덮어쓰지 않음 |
| 빌드 실패 | 원본 접근·검증 실패 시 새 빌드를 실패 처리. 수동 목록/가짜 빈 catalog로 대체하지 않음 |
| 기존 서비스 | 실패한 새 빌드가 기존 배포의 snapshot을 변경하지 않음. 이번 작업에서 배포 자체는 하지 않음 |
| 홈 런타임 | 정적 import한 snapshot으로 렌더·검색. 홈 catalog 요청 **0건**, 가격 요청 **0건** |
| 갱신 주기 | 다음 성공한 빌드 때 목록과 releaseId 갱신. 이번 단계에서는 브라우저 NAS 재검증을 넣지 않음 |
| 최신 목록 차이 | 기존 `/cbt/`는 기존 실제 데이터 경로 사용. 삭제/개명된 종목 이동 실패 시 기존 안내를 보존 |
| 개발/타입 검사 | clean checkout에서는 snapshot 생성 후 dev/tsc 실행. 누락 시 생성 안내와 오류; 손으로 JSON 생성 금지 |

공개 catalog에 없는 종목을 추가하거나 사람이 전체 목록 JSON을 채우지 않는다. 생성 산출물은 Git 커밋 대신 빌드에 포함한다. 롤백 빌드에서는 해당 소스의 생성 스크립트와 실제 catalog를 사용한다. 배포 이후 같은 releaseId의 정확한 산출물 복원이 필요하면 검증된 빌드 아티팩트를 보존한다.

## 푸터 정보와 미확정 사항

현재 `components/site-footer.tsx`에는 슬로건·저작권만 있고, 사업자정보·이용약관·환불정책 링크나 해당 app 경로가 없다. 사용자 답변으로 **페이지 하단 표시, 상호 딜라이트 커머스, 사업자등록번호 876-59-00934**가 확정됐다. 통신판매업 신고번호는 사용자가 추후 작성한다. 이용약관·환불정책 URL은 아직 전달되지 않았다.

| 정보 | 적용 기준 |
|---|---|
| 상호·사업자등록번호 | 푸터에 “딜라이트 커머스 · 사업자등록번호 876-59-00934” 표시. 모바일은 줄바꿈 허용, 글자 최소 14px |
| 통신판매업 신고번호 | 추후 제공 시 같은 사업자정보 영역에 추가. 임의 번호/더미 문구를 공개하지 않음 |
| 이미 있는 실제 외부/내부 페이지 | URL을 전달받아 연결, 기존 목적지 보존 |
| 사업자정보 링크 | 별도 페이지가 제공되지 않았으므로 위 정보를 하단에 직접 표시. 가짜 정보 페이지 링크를 만들지 않음 |
| 아직 미작성 | 미확정 상태로 기록. 정책·번호를 임의 작성하거나 `#`/404 링크를 만들지 않음 |
| 심사 대비 | 사업자정보 표시와 약관·환불 링크의 실제 대상 확인을 별도 검사. 신고번호 미입력 상태를 완료 보고에 명시 |

홈의 `/store/` 링크는 약관·환불정책 URL 답변과 무관하게 설계할 수 있다. 서버 HTML에 “핵심노트 스토어” 링크를 출력해 모든 폭에서 보이고, 로그인·NAS·가격 로딩·메뉴 열기에 의존하지 않게 한다. 스토어 상시 진입 링크와 확인된 법적 링크를 푸터에서도 숨기지 않는다.

| 푸터 | 제공된 상호/사업자등록번호 표시, 확인된 이용약관·환불정책 링크가 PC·모바일에서 정상 연결. 신고번호 미입력은 QA 보고서에 명시 |
| 화면 수치 | 보조 텍스트 최소 14px, 입력 본문 16px, 터치 최소 44×44px, 본문 대비 ≥4.5:1 |
| 넘침 | 360/390/430px에서 `document.documentElement.scrollWidth <= innerWidth` |
| 레이아웃 이동 | 홈 CLS ≤0.1. 검색 결과는 overlay 또는 사용자 입력에 따른 변경으로 처리 |
| 회귀 | 기존 `/cbt/`, 종목/시험/결과/오답, 상품/장바구니/결제/자료 경로 유지 |
| 브라우저 | Edge/Chromium·WebKit, 모바일 360/390/430 및 PC 768/1024/1280 전후 캡처 |
| 필수 검사 | `npm run check`, `npx tsc --noEmit`, `npx next build` 성공. snapshot 생성 누락 경로 검사 |
| 운영 경계 | 운영 배포·DB 쓰기·실결제·계약 변경 0건 |

가격·권한·주문 fixture를 이용해 회귀 검사한다. 실제 결제 버튼을 누르거나 운영 자료 발급/다운로드를 검증했다고 주장하지 않는다. 렌더가 폰트 가드 때문에 지연될 수 있는 기존 최대 1.5초 예산과 NAS 대기를 혼동하지 않는다.

## 커밋 구성과 롤백

현재 체크아웃은 앞선 작업의 수정·미추적 파일이 많다. 작업 전 기준 상태를 보존하고, 선행 작업을 이번 커밋에 섞지 않는다. 선행 작업이 필요한 기반 파일은 별도 확정된 기준 커밋/체크아웃으로 먼저 구분한다. 아래 C1/C2/C3는 **예정 라벨**이며 실제 SHA를 지어내지 않는다.

| 단위 | 예정 커밋 내용 | 단독 취소 의미 |
|---|---|---|
| C1 `feat(store): preserve storefront at store route` | 기존 홈을 유지한 채 `/store/`에 동일 상품 홈 추가 | 홈 전환 전에는 C1만 되돌릴 수 있음 |
| C2 `build(cbt): generate home catalog snapshot` | 생성기·빌드 연결·순수 데이터 helper·생성/검증 검사 | C3 취소 후 C2 취소 가능 |
| C3 `feat(home): activate learning home and search` | 루트 전환·검색·바로가기·최소 헤더 URL 변경·확인된 푸터 링크·14px CSS·문서/캡처 | **주 롤백 단위**. 되돌리면 루트가 기존 상품 홈으로 돌아옴 |

C1은 기존 상품 홈의 복사/이동 준비를 독립시킨다. C3 롤백 후에도 `/store/`가 남아 새 URL을 이용한 사람에게 404를 주지 않는다. C3는 C1·C2의 SHA와 사용 snapshot releaseId를 QA 문서에 기록한다. 각 커밋에는 그 변경의 검사를 함께 넣는다.

```text
홈 전환만 롤백
  git revert <C3 실제 SHA>
  필수 검사 + / 및 /store/ + 헤더/푸터 회귀 확인
  → /는 이전 상품 홈, /store/도 계속 접근 가능
  → 코드 롤백만 수행. 운영 재배포는 별도 승인 범위

스냅샷 도입도 롤백
  C3가 취소된 상태에서 git revert <C2 실제 SHA>
  → 빌드 생성 hook/helper 제거. C1의 /store/는 보존

신규 경로까지 완전 취소
  C3 → C2 → C1 순으로 revert
  → /store/ 제거. 이미 외부에 공개했다면 이 단계는 피하고 C1 유지
```

현재 dirty 작업 위에서 바로 revert하지 않는다. 실제 구현 커밋만 식별하고 작업 트리를 보존한 뒤 적용한다. `reset --hard`, `git clean`, 운영 DB 롤백, 인증/결제 키 변경은 사용하지 않는다. snapshot 산출물은 추적하지 않는 생성 파일이므로 불필요한 파일은 명시 경로를 확인한 후만 정리한다.

## D 적용용 구현 지시문

```text
PASSMATE 학습 홈 1단계만 구현한다. 본 문서의 파일 목록·완료 기준을 따른다.

1. 기존 dirty 상태와 계약을 기록하고 실제 기준 커밋을 확정한다.
   선행 작업과 이번 작업을 섞지 않는다. 계획을 보여준 뒤 코드 적용으로 진행한다.

2. C1: app/store/page.tsx에 현재 루트의 상품 홈을 보존한다.
   기존 HomeProducts, 서버 가격 조회, 가격 skeleton/재시도, SKU/CTA 유지.
   이 시점에는 /의 상품 홈을 제거하지 않는다.

3. C2: scripts/generate-cbt-home-catalog.mjs를 구현한다.
   공개 catalog 한 개만 읽어 schema/releaseId/종목과 수치를 검증한다.
   전체 목록을 자동 변환해 generated JSON을 원자적으로 쓴다.
   source hash와 generatedAt을 기록한다. 사람이 목록을 작성하지 않는다.
   원본 오류/timeout은 빌드 실패로 처리하고 기존 파일을 보존한다.
   next.config.ts production build에 연결해 npm build와 npx next build를 모두 지원.
   package.json에 catalog:snapshot 명령·검사를 추가하고 기존 검사를 보존한다.

4. C3: app/page.tsx를 learning-home으로 바꾼다.
   생성 JSON의 정적 import만 사용한다. NAS·가격 조회를 제거한다.
   제목, 검색, 실제 바로가기, 전체 종목 링크, 상시 /store/ 링크를 서버 HTML에 표시.
   바로가기는 실제 목록에서 결정적으로 선택한다. 인기 통계라고 표현하지 않는다.
   검색 결과는 기존 certSlug 규칙과 같은 종목 URL로 이동한다.
   combobox 키보드/스크린리더 동작을 구현한다. 시험을 자동 생성하지 않는다.

5. 헤더 메뉴 구조와 서비스 전환을 유지한다.
   스토어 href만 /store/로 옮기고 /의 학습 활성 상태와 /store/ 스타일 범위를 보정.
   메뉴 통합·하단 탭·브랜드 전면 변경을 추가하지 않는다.
   로그인/메뉴 상태가 홈의 /store/ 링크를 숨기지 않게 한다.

6. 페이지 하단 푸터에 “딜라이트 커머스 · 사업자등록번호 876-59-00934”를 표시한다.
   통신판매업 신고번호는 추후 제공 후 같은 영역에 추가한다.
   약관/환불정책은 실제 URL을 받은 뒤 연결한다. 가짜 정책·번호·# 링크 금지.
   URL 미확정과 신고번호 미입력은 완료 보고에서 별도로 남긴다.
   모바일에서도 사업자정보·확인된 법적 링크·스토어 진입을 숨기지 않는다.

7. 새 홈 CSS를 범위 제한해 적용하고 기존 색 변수를 사용한다.
   학습 홈/이전된 스토어/해당 헤더·푸터 보조 텍스트는 최소 14px.

   토큰 전면 개편·오답 후 노트 연결·이어풀기는 이번에 하지 않는다.

8. 성공 catalog와 지연/실패 fixture로 검사하고 전후 캡처를 제공한다.
   360/390/430px 모바일 및 768/1024/1280px PC, Edge/Chromium과 WebKit.
   NAS/가격 차단에도 홈 검색이 동작하며 홈 관련 NAS/가격 요청은 0건이어야 한다.

9. 모든 필수 검사 통과 후 실제 C1/C2/C3 SHA와 snapshot releaseId를 기록한다.

```

현재 미확정 입력은 **이용약관·환불정책의 실제 URL 및 통신판매업 신고번호**다. 상호·사업자등록번호·하단 배치는 확정됐다. 홈·검색·snapshot 작업과 미확정 정보는 구분하고, 미제공 정보까지 완료했다고 보고하지 않는다.
