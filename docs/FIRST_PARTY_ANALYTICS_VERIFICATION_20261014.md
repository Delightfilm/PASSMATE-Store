## 실제 수집→저장→화면→CSV

운영자의 정상 메인 진입, 문제은행 이동, 분석 설정(비공개) 이동을 사용했다. 운영 DB에 가짜 집계나 회원 응시를 삽입하지 않았다. 초기 집계에는 이 운영자 검증 방문이 포함된다.

성공한 실제 패킷17개(모두204)는 다음 합과 일치했다.

| 항목 | 브라우저 패킷 합 | DB 전체 합 | 관리자 / CSV |
| --- | ---: | ---: | --- |
| 조회 |2|2|2|
| 방문 시작 |1|1|1|
| 활성 밀리초 |298749|298749|CSV298749, 화면4분59초|
| 조회당 활성 시간 |총 시간/2|총 시간/2|2분29초|

페이지별 home=1/1/33946ms, cbt=1/0/264803ms, 유입unknown=2/1/298749ms와 전체 주변 합이 일치했다. 첫 패킷 nonce의 해시 영수증도 확인했다. 분석 설정으로 이동한 뒤 합계가 증가하지 않았다. CSV는 실제 다운로드된625byte 파일을 읽어 전체/일별 수치와 출처·기간·정의·제한을 대조했다. 다운로드 이벤트 도구는 timeout이었지만 실제 파일 생성과 내용 검증은 성공했다.

실제 wire 요청17개 모두 Cookie/Authorization/Referer가 없고 수집 응답에 Set-Cookie가 없었다. 공개 패킷은 버전·nonce·주변 카운터뿐이다. Supabase 직접 연결의 Cloudflare 보안 쿠키는 서버 응답에 있었지만 Next가 원 응답 헤더를 복사하지 않아 방문자에게 전달되지 않았다.

Supabase 실제 함수 로그의 필드 이름을 확인했다. 기본 인프라 요청 메타데이터(서버 연결 IP/UA 등)는 있으나 집계 본문·원시 방문 주소·전용 토큰·방문자 Cookie/Auth/Referer를 복제하지 않는다. 원 요청 헤더를 후속 요청에 전달하지 않는 핸들러 검사도 통과했다. Vercel 외부 log drains는0이며 새 본문 로그/추적 모듈은 없다. 호스팅/보안 사업자의 HTTP 처리가 전혀 없다고 주장하지 않는다.

## UI·선택·기존 데이터

메인/SPA/설정 화면에 자동 배너·dialog가 없다. 설정3개 버튼과noindex를 확인했다. 설정과 관리자 모두 실제390px 모바일 emulation에서 width/scrollWidth390이며 override를 해제했다. 소량 묶음·기간 입력 오류·측정 전 구간(숫자 카드0개)·CSV·별도 GA4를 실제 화면에서 확인했다. 기존 GA4는 오류 없이7개 카드, 인기 시험은 총 응시34/완료6/응시 회원2로 표시됐다. DB 응시34/주문7 유지도 대조했다. 관리자 로그인은 로그아웃하지 않았다.

신규 선택의 기본 요청/GA4 미호출과 기존 거절·모든 선택·저장 오류·다른 탭·GPC·늦은 비동기 중지는 실제 모듈을 실행한 결정적 테스트로 검증했다. 비로그인 API401, anon/authenticated의 표/RPC 접근 불가와 관리자 실제 조회를 확인했다. 별도 일반 회원으로 실로그인하는 시나리오는 실행하지 않았다. GPC를 실제 브라우저에서 임시 주입하는 방법은 지원되지 않아 실제 GPC 브라우저 실측은 미검증이며 브라우저 신호 우선 판정/이벤트 차단 실행 테스트로 확인했다. 실제 사용자 선택은 자동으로granted로 바꾸지 않았다.

## 구현 중 판단과 비용

1. Windows 경로로 스킬 기록 도구가 실행되지 않아 PowerShell/Node 방식으로 같은 작업별 기록과 테스트 게이트를 유지했다. 잘못됐을 경우 커밋·검사 로그로 기록을 복원해야 한다.
2. 큰 migration 요청이 간헐적으로 만료되어 QA 적용을 표/함수별로 나눴다. 정의와 권한은 동일하고 운영 core는 한 번에 적용했다. QA 이력을 추적할 때 여러 적용 항목을 확인해야 한다.

미룬 사소한 코드 지적은 없다. CI/브라우저 도구의 제한을 성공으로 바꿔 기록하지 않았다.
