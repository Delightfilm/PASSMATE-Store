# PASSMATE Design System

## 최근 로그인 배지 (2026-10-09)

- 로그인 방식 버튼 하나의 오른쪽 위에 `최근 로그인` 작은 알약 배지를 표시한다. 색은 기존 `--blue-soft` / `--blue-dark` / `--blue-line`, 글자 12px / 600, 패딩 3px 8px이다. 독립 버튼이 아니며 부모 버튼의 44px 이상 터치 영역을 보존한다.
- 버튼의 기존 문구·중앙 정렬을 유지한다. 로그인 화면 SNS 버튼 간격은 18px로 고정하여 배지가 버튼 문구와 겹치거나 표시 후 레이아웃을 이동시키지 않게 한다. 가입 화면에는 배지를 넣지 않는다.
- 이 브라우저의 마지막 성공 방식만 기록한다. 상세 동작과 검증 한계는 `docs/AUTH_RECENT_LOGIN.md`를 따른다.

## 첨부 HTML 푸터 적용 (2026-10-05 · 최신)

- 사용자 제공 `PASSMATE Home.dc.html` 푸터를 기준으로 짙은 배경, 상단 `© 2026 PASSMATE` + 서비스 메뉴, 가로 구분선, 항목별 `dt/dd` 사업자 정보 격자를 적용한다. 아래 이전 배치 기록보다 이 규칙을 우선한다.
- 최대 폭 1120px, PC 좌우 24px / 모바일 ≤767px 좌우 16px. 사업자 정보는 최소 열 폭 240px의 반응형 격자이며 360~430px에서는 1열이다. 모바일 메뉴는 2열, 모든 링크는 44px 이상이다.
- 첨부안 13px 대신 기존 접근성 기준인 최소 14px를 유지한다. 색은 전용 푸터 CSS 토큰에서 관리한다. 인증·결제·다운로드·시험 화면 숨김·safe-area 규칙은 보존한다.
- 통신판매업 신고번호는 사용자 확정 정정값 `2026-서울노원-1344`로 설정한다. 공개 정보는 `lib/business-info.ts` 한 곳에서 관리하며 빈 필드는 렌더링하지 않는다.

## 푸터 배치 재조정 (2026-10-05)

- 사용자가 짙은 푸터 배치를 반려하여 밝은 배경, 브랜드/슬로건 상단, 내부 가로 구분선, 사업자 정보, 마지막 저작권 순서를 복원한다. 과거 참고 화면은 정보 종류를 참고하는 용도이며 배치/배경을 그대로 복제하지 않는다.
- 서비스 링크는 PC 우측/모바일 2열로 정렬한다. 사업자 정보는 상호·등록번호·대표 / 주소 / 신고번호·이메일의 묶음으로 줄여 표시한다. 확인된 내용과 이메일 라우팅 설정은 보존한다.
- 전용 푸터 토큰만 밝은 기존 팔레트로 변경한다. 최소 14px·44px·safe-area 및 시험 푸터 숨김 규칙을 유지한다.

## 공통 푸터 참고 화면 반영 (2026-10-05)

- 사용자 요청에 따라 PC/모바일 공통 푸터를 작은 저작권 표기 + 서비스 링크 + 사업자 정보로 정리한다. 문제은행 / 스토어 / 내 자료 / 문의만 포함하며 포담·그룹앨범·없는 커뮤니티 링크는 만들지 않는다.
- 짙은 푸터는 `--footer-surface`, `--footer-foreground`, `--footer-secondary`, `--footer-link`, `--footer-border`로 기존 팔레트를 참조한다. 다른 화면의 색/레이아웃을 변경하지 않는다.
- 모바일 ≤767px 링크는 2열, 터치 높이 44px, 사업자 정보는 접지 않고 항상 표시한다. 본문/보조 최소 14px, 줄 간격 1.6, 이메일 긴 문자열 줄바꿈을 유지한다.
- 대표 김주환 / 주소 서울특별시 노원구 상계로 35길 15-8 / 이메일 report@mypassmate.com / 신고번호 2026-서울노원1344는 사업자 설정 하나에서 가져온다.
- 전화번호는 사용자 지시에 따라 공개하지 않는다. 전화번호도 법정 표시 항목이므로 완전한 표시 의무 이행을 주장하지 않는다. 약관 본문 확정 전 법적 페이지 링크는 추가하지 않는다.
- 시험 응시 화면 푸터 숨김과 구매 바·미래 하단 탭 safe-area 여백은 유지한다.

## 학습 홈 1단계 (2026-10-05)

- 루트 `/`는 학습 홈, 기존 판매 홈은 `/store/`다. 기존 스토어 모바일 규칙은 `/store/` 및 상품/자료 화면에 계속 적용한다.
- 이번 사용자 승인에 따라 PC 홈도 변경한다. 메뉴 통합·하단 탭은 추가하지 않는다.
- 제목 32px(PC 48px), 본문 16px, 보조 최소 14px. 제목 700 / 카드 제목 600, 컨트롤 최소 44px, 모바일 좌우 16px. 색은 기존 토큰만 참조한다.
- 바로 풀 자격증은 실제 snapshot의 문제 수 기준이다. 모바일 4개 / PC 6개, 검색은 이름·초성·컴활 별칭과 키보드 이동을 지원한다.
- 학습 홈은 폰트·NAS·가격 응답을 기다리지 않는다. 판매 화면의 최대 1450ms 폰트 폴백은 유지한다.
- 사업자 정보는 모든 폭에서 표시한다. 빈 필드는 숨기고 보조 텍스트도 14px / 줄 간격 1.6을 유지한다. 저작권은 사업자 정보 다음에 배치한다.
- 미래 하단 탭 여백은 `--bottom-nav-height` 기본 0과 `env(safe-area-inset-bottom)`을 사용한다. 이번에 하단 탭 자체를 만들지 않는다.

## 스토어 모바일 규칙 (2026-10-04)

- 홈 / 상품 목록 / 상품 상세 / 내 자료는 `app/store-mobile.css`의 767px 이하에서만 레이아웃을 보완한다. 768px 이상은 기존 디자인을 유지한다.
- 헤더 콘텐츠 높이 56px(상단 안전영역 별도), 로고 및 메뉴를 상단에 배치하고 서비스 전환은 바로 아래에 둔다. 요약노트 / 내 자료는 기존 메뉴에서 접근한다.
- 홈 대표 핵심노트와 중복되는 비교 카드는 모바일에서 숨긴다. 상세 비교는 두 패키지의 체크리스트 카드와 하단 구매 바를 사용한다.
- 색은 기존 브랜드 색을 토큰으로 참조한다. 본문 15px / 보조 13px / 뱃지 12px, 터치 영역 44px, 좌우 16px, 안전영역 및 구매 바 여유 공간을 확보한다.
- 운영 가격은 공개 active SKU를 서버에서도 조회해 초기 HTML에 포함한다. 브라우저는 초기 조회 / 포커스 / 재시도 시 가격을 갱신한다. 대기 중 고정 skeleton 및 비활성 구매하기, 실패 시에만 다시 시도를 표시한다. 실제 결제는 기존 DB 가격 검증을 유지한다.

## 1. 기본 원칙

PASSMATE의 핵심노트와 시험대비 완성패키지는 **같은 디자인 시스템의 Light / Dark Variant**로 운영한다.

서로 다른 브랜드처럼 디자인하지 않는다.

공통:
- 동일한 Typography
- 동일한 Grid
- 동일한 Header/Footer
- 동일한 표 스타일
- 동일한 도식 스타일
- 동일한 Badge 체계
- 동일한 기하학적 디자인 언어

## 12. 웹서비스 공통 UI

### 웹 타이포그래피와 간격 토큰 (2026-10-03)

- 단일 정의: `app/tokens.css`. 화면별 적용은 `app/globals.css`와 `app/ui-refinements.css`에서 토큰을 참조한다.
- Pretendard Variable v1.3.9를 `next/font/local`로 제공한다. `font-display: swap`, 굵기 범위 45–920. 시스템 대체 순서는 system-ui, -apple-system, Apple SD Gothic Neo, Noto Sans KR, sans-serif이며 별도 Inter는 사용하지 않는다.
- h1: 자간 -0.025em / 행간 1.28 / balance. h2: -0.02em / 1.3 / balance. h3 및 카드 제목: -0.015em / 1.4.
- 본문: 자간 0 / 행간 1.6 / pretty. 부제: 1.5. 작은 설명: 최소 13px / 1.55. 버튼: 최소 13px, 주요 버튼 14px / 높이 44px 이상.
- 한글 라벨 자간 0.01em. 영문 대문자에만 `eyebrow--latin` 또는 `pill--latin`으로 0.12em을 지정한다. `word-break: keep-all`을 유지한다.
- 시험 문제: 자간 -0.01em / 행간 1.5 / 굵기 600 / pretty. 보기: 16px / 1.5, 22px 원형 숫자 배지. 결과 해설: 15px / 1.6. 시간·점수·가격은 tabular-nums.
- 간격은 4/8/12/16/24/32px 토큰을 사용한다. 모바일 비교표는 선택한 패키지 열만 보여주고, 안내 목록은 1열로 배치한다.
- 상품 갤러리 `pages`에 실제 이미지가 있을 때만 썸네일을 표시한다. 내부 제작 안내 문구는 고객 화면에 표시하지 않는다.


- 스토어 표기는 `PASSMATE`, 문제은행 표기는 `CBT MATE`로 통일한다. CBT 경로의 헤더 로고는 CBT MATE 홈으로 연결한다.
- 네이비·파랑과 둥근 pill/카드 스타일을 유지한다. 메뉴와 주요 동작의 터치 영역은 최소 44px, 본문 텍스트 대비는 최소 4.5:1로 잡는다.
- 맞춤 시험지의 과목별 문항 수는 숫자 직접 입력과 44px 감소/증가 버튼을 묶은 컨트롤로 표시한다. 모바일에서는 과목명 아래 전체 폭으로 배치한다. 모의시험 구성 카드는 모바일 한 열로 배치한다.
- 모바일 제목은 한글 어절을 유지하며 줄바꿈한다. 오답 필터는 한 줄에서 가로 스크롤하고, 결과 하단 고정 바에는 주요 동작 두 개만 둔다.
- 한글 어절 보호는 `body` 전체에 적용한다. 긴 이메일 등 예외 콘텐츠만 `overflow-wrap: anywhere`를 쓴다.
- 운영 CBT 카탈로그 조회가 실패하거나 비어 있으면 샘플 문항을 표시하지 않고 오류와 다시 시도 동작을 제공한다.
- 만료 응시는 확인 모달에서 사용자가 확정한 뒤에만 제출한다. 응시 화면 조회는 서버 응시 상태를 변경하지 않는다.
- 헤더는 1180px 컨테이너 안에서 로고 슬롯(184px) → 40px 간격 → 왼쪽 정렬 메뉴, 오른쪽에는 `스토어 / 문제은행` 전환과 계정 버튼을 둔다. 제품별 로고는 각각 `PASSMATE`, `CBT MATE`로 표기한다.
- 헤더 메뉴 항목은 8px 간격과 좌우 12px 패딩을 사용하며, 현재 메뉴의 밑줄은 두 제품에서 같은 파랑 2px이다. 모바일에는 로고 심볼·압축 전환·계정 버튼을 한 줄에 둔다.
- 일반 컨트롤은 파란 3px `:focus-visible` 링 하나를 사용한다. 검색처럼 입력을 둥근 래퍼가 감싸는 경우에는 입력 링을 없애고 래퍼 전체에 `:focus-within` 링을 둔다.
- 메인은 상품 표지·상품명·운영 가격·상세 링크를 첫 화면에 배치하고, 핵심노트/완성패키지 구성을 두 카드로 비교한다. 현재 최종 표지 이미지 파일은 저장소에서 확인되지 않아 기존 상세 페이지의 표지 컴포넌트를 사용한다.
- 스토어 ≤767px에서는 대표 핵심노트와 완성패키지 카드 한 개를 표시한다. 비교 영역 제목은 “완성패키지 구성도 살펴보세요.”이며 대표 상품의 모바일 CTA는 “핵심노트 자세히 보기”다. 데스크톱 문구는 유지한다.
- 모바일 첫 화면의 폰트 준비 대기는 최대 1.5초 예산으로 제한하며 1450ms 타이머로 기본 폰트를 표시한다. 폴백 표시 후 늦게 도착한 웹폰트로 다시 교체하지 않는다.
- app/components의 색 참조는 tokens.css를 단일 원본으로 사용한다. 기존 라이트 팔레트와 표지/로고 색 값은 변경하지 않는다. 조사표는 docs/STORE_COLOR_INVENTORY.md에 기록한다.
- 스토어 문구는 docs/STORE_COPY_INVENTORY.md의 정보 손실 기준으로 정리한다. 페이지 제목 700, 카드/섹션 제목 600, 본문/보조 400은 사용자가 데스크톱 적용도 허용했다. 그 외 이번 레이아웃 변경은 app/store-copy.css의 max-width:767px에만 둔다.
